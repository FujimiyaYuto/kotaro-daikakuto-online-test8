# コタロの大格闘 Online — Online Phase 9 完成報告

「KO・3 ストック・リスポーン・無敵・勝敗の同期」。Phase 8 までの同期方式（HOST authoritative・GUEST 予測＋reconciliation・70ms 補間・
近接攻撃の遅延補償・泡は HOST 判定・ガードは HOST の今の状態）をそのまま使い、HOST authoritative な 3 ストック制の 1 試合を最後まで成立させました。
ルールの数値は Version 1.0 のまま（`KG.CONFIG.rules`：3 ストック・リスポーンまで 1.0 秒・無敵 2.0 秒、場外ラインは stage.js、勝敗表示まで 1.3 秒）。
技・吹っ飛び・移動・ルミポの復帰性能・遅延補償の上限・補間の遅れは変更していません。

## 1. 仕組み
| 項目 | 内容 |
|---|---|
| KO（HOST） | 場外の判定・ストック -1・リスポーン・ダメージ 0・無敵は既存の `StockRules` がそのまま行う（Phase 8 まではストック Infinity にしていたのを 3 に戻しただけ）。既存の `onKnockOut` の後で KO を記録し、ステップの終わりに **KO イベント `mk`** を 1 回送る：KO 番号（試合内で一意）・KO された側・残りストック・その側の KO 回数（命の番号）・場外の位置・試合結果。|
| 状態 `st` | 両者の `[10]` 残りストック・`[11]` KO 回数と、試合結果 `r`（0 試合中 / 1 コタロ / 2 ルミポ / 3 引き分け）を毎回（30Hz）載せる。イベントが遅れても状態で必ずそろう。|
| ストック（GUEST） | HOST の値（絶対値）をそのまま表示。自分で引き算しない。KO 番号で重複を捨て、KO 回数が古い値では上書きしない → 同じ KO が何度届いても二重に減らない。HUD は既存の `RulesHud`（ダメージ・ストックの丸・復帰待ち「—」・ストック 0 の「KO」）。|
| KO の演出（GUEST） | KO イベント 1 件につき既存の `onKnockOut`（場外の合図・KO 音）を 1 回。予測のルミポが先に場外へ出て見えても、ストック・KO は HOST のイベントまで確定しない（今までどおり表示を隠して待つだけ）。|
| リスポーン（GUEST） | 「命の番号が変わった HOST 状態」を明確な状態遷移として扱う：予測用ルミポを HOST の状態に置き換え、死亡前の予測（見た目だけ続けていた技・HOST 未確認の予測泡・表示のずれ・被弾補正）を捨てる。未確認入力は HOST が適用済みの分を捨て、残り（リスポーン後に HOST が適用する入力）だけを適用し直す。補間は命の番号が違う 2 つの状態の間では行わない。|
| 無敵 | 成立は HOST の既存 `Combat`（`canBeHit`。遅延補償の過去位置を使う時も、受けられるかは HOST の今の状態）。残り時間は Phase 2 からある状態の `[6]` で同期し、GUEST も既存の点滅（`KG.invincibleAlpha`）で表示。|
| 試合終了（HOST） | 既存の `onFighterKO`（最後のストック）は勝者をすぐ決めず記録だけし、そのステップの KO をすべて集めてから結果を確定。`result` / `winner` / `phase = 'ending'` は Version 1.0 と同じ値を使い、1.3 秒後に既存の勝敗表示。残っている泡は消滅イベント（理由 = その他）を送ってから消す。|
| 試合終了（GUEST） | `mk` の `r` または状態の `r` で 1 回だけ終了処理（自分で勝者を計算しない）。以後は予測しない・未確認入力を捨てる・何も押していない入力だけを送る・命中イベントを無視・泡を薄く消す。勝敗のジングルは自分（ルミポ）視点で選ぶ。|
| 終了後に状態が変わらない理由 | HOST は既存の `Game.step` が試合中以外の入力を捨て、戦闘判定をせず、泡を出さない。Phase 3 の「入力の追いつき」も試合中だけにした。終了後に場外へ出てもストック・勝者は変えない（表示から外すだけ）。|
| 勝敗表示 | 既存の `#ko-overlay` に同じ「〇〇 WIN」/「DRAW」。オンラインでは「もう一度」「タイトルへ戻る」を隠し、「実験を終了」で接続画面へ（Esc も止める）。|
| 切断 | 変更なし（今までどおり実験を終了して接続画面へ。切断勝ちなどは無し）。|

### 同時 KO のルール
Version 1.0 には同時 KO の明確な仕様が無く、処理順（コタロが先）で「ルミポの勝ち」になる。オンラインでは HOST が常にコタロ側になるため、次の最も単純なルールにした：
- **同じステップで両者が最後のストックを失った → 引き分け（DRAW）**。
- 1 ステップでも違えば、先に最後のストックを失った側の負け。その後の場外はストック・結果を変えない。

項目：開始 3/3、HOST KO → 3→2 → 約 1 秒でリスポーン・ダメージ 47→0・無敵 約 2 秒、GUEST KO → 3→2（KO イベント 1 件ずつ）・リスポーン・ダメージ 0、
GUEST が右を押したまま KO → 死亡中に離す → リスポーン後の予測位置 = HOST 位置（古い入力で動かない・snap 0）、無敵中のぽよん → HIT なし、無敵終了後 → HIT（両画面ダメージ一致）、
連続 KO 3→2→1→0 → コタロ WIN（両画面一致）、終了直前の泡 → 両画面で消える、終了後の GUEST の攻撃・泡・移動・HOST の攻撃・必殺・偽の命中イベント → stock / damage / 勝者 変化なし、
勝敗表示が両画面で同じ、最後の KO イベントを 2 回再送 → 重複 2・ストックの二重減少なし、GUEST 勝利（ルミポ WIN・両画面一致）、
同じステップの最後の KO → DRAW（両画面）、1 ステップ違いの KO → 先の側の負け・後の側のストックは減らない、終了後に差し替えが元へ戻る。

## 5. 遠隔実機で後から確認すること
1. KO の演出・音が 1 回だけか、両画面のストックが同じか。
2. リスポーン直後に自分（ルミポ）が勝手に動いたり、死亡前の位置へ戻ったりしないか。
3. 無敵中の点滅が両画面で見えるか、無敵が切れた直後の攻撃が普通に当たるか。
4. 最後の KO から勝敗表示まで、両画面で同じ勝者が出るか。終了後に操作しても何も起きないか。
5. 「実験を終了」→ もう一度「操作実験を開始」で 3/3 から始まるか。
