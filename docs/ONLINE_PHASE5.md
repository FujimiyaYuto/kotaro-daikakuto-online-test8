# コタロの大格闘 Online — Online Phase 5 完成報告

「近接攻撃（ぽよんアタック）の Lag Compensation 実験」。GUEST → HOST の攻撃だけが対象。
HOST authoritative は維持（命中・ダメージ・吹っ飛びを決めるのは HOST だけ）。表示（予測・70ms 補間）は Phase 4 のまま。
rollback・ゲーム世界の巻き戻し・必殺技・泡・ガード・KO・勝敗・ルミポの性能調整は行っていません。

## 1. HOST の履歴
- 毎ステップ（60 回/秒）、コタロの Hurtbox を作るのに必要な値だけを保存：**x, y, 向き, 場にいるか, 被弾した回数**（＋ステップ番号）。速度・技・その他の状態は保存しない。
- リングバッファ **36 ステップ = 600ms 分**（巻き戻しの上限 200ms ＋ 余裕）。
- 「送った状態の番号 → その状態のステップ番号」の対応も直近 **40 件（約 1.3 秒）** だけ保存。
- 履歴は HOST 内部だけ。GUEST へは送らない。

## 2. 時間参照（GUEST が送るもの）
- GUEST は攻撃を押した入力にだけ、2 つの数を付ける：
  - `rs` = その瞬間、画面のコタロの補間に使っていた **HOST 状態の番号**（HOST が発行した番号）
  - `rf` = その状態から次の状態までの **割合 ×1000**（新しい状態が遅れて先へ伸ばしている時は 1000 を超え、最大 3000）
- 座標・時刻・「当たった」などは送らない。ブラウザの時計の一致も前提にしない。

## 3. HOST での検証と巻き戻し量
- HOST が攻撃の押下を適用した瞬間（Phase 3 の入力キューから取り出した時）に計算：
  1. `rs` が **自分が実際に送った番号の記録にあるか**（未来・存在しない・古すぎて記録に無い → 「不正な参照」として数え、巻き戻さない＝今の位置で判定）
  2. 参照ステップ = その状態のステップ + 割合 ×（次の状態までのステップ数）。今より未来なら不正
  3. 巻き戻し量 = 今のステップ − 参照ステップ。**上限 200ms**（12 ステップ）を超えたら 200ms にする（上限到達として数える）
- 範囲外の値（`rf` > 3000 など）はメッセージごと破棄。
- この巻き戻し量は、その押下から始まった攻撃に結び付けられる（攻撃 ID は Phase 4 と同じ）。

## 4. 過去 Hurtbox の再構築と判定
- 判定の仕組みは既存の `Combat.resolve()` のまま。HOST のコタロの `getHurtboxes()` だけを（このインスタンス・操作実験中だけ）差し替え：
  **ルミポのぽよんアタックの判定が出ているステップで、遅延補償 ON の時だけ**、「今 − 巻き戻し量」の位置（履歴の前後 2 ステップから補間）にコタロの既存の Hurtbox 定義を置いた矩形を返す。それ以外は今の Hurtbox。
- ルミポ（攻撃側）は巻き戻さない：GUEST の画面のルミポは予測で「今」に近く、HOST のルミポの攻撃判定も HOST の今の状態なので、巻き戻す必要がない（予測が HOST とほぼ一致することは Phase 3 で確認済み）。
- コタロの本当の位置は動かさない。命中したらダメージ・吹っ飛び・ヒットストップ・被弾状態は既存処理で「今の」コタロに適用。rollback なし。
- 次の場合は巻き戻さない（今の位置で判定）：参照した過去から今までに、コタロが**被弾した・場外/復帰した・瞬間移動した**、または今コタロが場にいない。
  → 「被弾して飛ばされた後に、飛ばされる前の位置を殴る」「復帰前の位置を殴る」を防ぐ。
- HOST（コタロ）→ GUEST（ルミポ）の攻撃には使わない（HOST は今の状態を見ているため）。

## 5. 上限 200ms の決め方
- 必要な巻き戻し量の実測（＝ GUEST の画面のコタロと HOST の今の差の時間）：Ping 約 30ms → 約 155ms、約 60ms → 約 185ms、約 100ms → 約 225ms、約 200ms → 約 320ms
  （内訳：入力が HOST に届くまで ＋ HOST での待ち ＋ 状態が届くまで ＋ 状態の間隔 ＋ 補間 70ms）
- 上限 150 / 200 / 300ms を同じ条件で比較（6 章）：
  - 150ms：Ping 30〜60ms でも毎回上限に当たり、補償が足りない
  - **200ms：実測の遠隔 Ping（29〜57ms）では上限に当たらずほぼ全量補償。Ping 100ms 以上は部分補償。**
  - 300ms：見た目との一致はさらに良くなるが、HOST から見て「離れていたのに当たった」距離が最大 250（コタロの体 3 つ分以上）まで伸びる
- コタロの最高速度 440/秒 → 200ms の巻き戻しで逃げられる距離は横に最大 約 88（体の幅 76 程度）。これ以上の巻き戻しは HOST 側の違和感が大きいと判断。

## 7. ON / OFF の比較方法
- HOST の画面上部「LagComp ON / OFF」ボタン、または **C キー**で実験中いつでも切替（URL `?lagcomp=off` で最初から OFF、`?lagmax=150` などで上限を実験用に変更：0〜300）。
- OFF = Phase 4 と同じ「今の位置」の判定。
- ON / OFF どちらでも、HOST は各攻撃について「今の位置なら HIT か」「遅延補償の位置なら HIT か」を両方記録する（診断のみ）。GUEST の診断には実際の 4 分類と、「今の位置で判定した場合」の 4 分類を並べて表示。
