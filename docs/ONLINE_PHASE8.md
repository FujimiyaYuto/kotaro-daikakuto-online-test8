# コタロの大格闘 Online — Online Phase 8 完成報告

「ガードのオンライン同期」。Version 1.0 の既存ガードを、HOST authoritative のままオンライン実験に追加しました（短時間の代表テストのみ）。
ガードの性能は変更していません：I / スマホ「防御」、地上のみ、出始め 3F（この間は防御無効）、正面からの攻撃だけ防ぐ（攻撃してきたもの＝キャラ / 泡の位置とガードの向きで判定）、
成功時はダメージ・吹っ飛びなし・ヒットストップ 4F・押し戻し 420・ガード硬直 10F、ガード中は移動・ジャンプ・攻撃不可（押した攻撃は捨てる）、空中でガードは始まらない
（押したまま着地すると着地後に始まる＝v1.0 のまま）。v1.0 では技ごとのガード不能は無く、ぽよん・クラゲ電撃・バブルショットはすべて正面ならガードできます（そのまま再現）。
ガード用の遅延補償・rollback・パリィ等は行っていません。

## 1. 仕組み
| 項目 | 内容 |
|---|---|
| 入力 | 毎回の入力 `mi`（60 回/秒。止まっていても送る）に **`g` = ガードを押しているか (0/1)** を追加。押した回数ではなく状態。HOST は既存の `cmd.held.guard` に渡すだけ。入力が届かない間は直前の状態を続け、500ms 届かなければニュートラル（Phase 2 の仕組み）。成功・方向・位置などは送らない。|
| GUEST の予測 | 同じ入力を予測用ルミポ（既存の Fighter）に適用するので、押した次のフレームからガードの姿勢（既存の身をかがめる変形と正面の半円の膜）が出る。予測は見た目だけで、防げたかは決めない。HOST 状態にガードの状態・経過フレーム・硬直の残り・向きを載せ、予測を HOST に合わせてから未確認の入力を適用し直す（Phase 3 と同じ）。|
| HOST の判定 | 既存の `Fighter`（地上・出始め・有効・硬直）と `Combat.resolve` の `canGuardAgainst`（正面か）がそのまま判定。成功は既存の `receiveGuard`、失敗は既存の `receiveHit`。近接攻撃の遅延補償は「当たる位置」に使うだけで、ガードできるかは HOST の今の状態で判定（巻き戻しなし）。|
| 結果のイベント | ガード成立は命中イベント `mh` に `g=1` を付けて、通常の HIT と **同じ番号の列** で送る。1 つの攻撃は既存の `hitVictims` により HIT か GUARD のどちらか 1 回だけ。GUEST は番号ごとに 1 回だけ表示（重複は数えて捨てる）。攻撃 ID / Projectile ID で HIT と GUARD の二重も監視。|
| 予測と HOST が違った時 | ガードの結果（押し戻し・硬直）も被弾と同じく「HOST の結果を優先」の補正（30ms で寄せる・300 以上で即座に）。予測ではガード中だったのに HOST は HIT（背面・出始め・入力が間に合わない）→ 被弾状態へ。予測では解除していたのに HOST はガード → ガード硬直へ。|
| 音・演出 | 既存のガード音 `guard` とガードの演出 `spawnGuard`。GUARD イベント 1 件につき 1 回。GUARD の時は命中音・命中の演出を出さない。泡をガードした時は泡が弾ける（v1.0 と同じく消える）。|
| HOST 側のガード | コタロも I / タッチの防御ボタンでガードできる（以前の Phase で外していたのを戻した）。GUEST の画面のコタロにもガードの姿勢が出る（状態のフラグ）。|

## 2. 代表テスト（短時間・人工遅延。各条件 約 1 分・23 項目）
ガード開始 / 解除（GUEST・HOST）、GUEST が正面ガード × コタロのぽよん・電撃・泡、背面からのぽよん（ガード中でも HIT）、ガードなし、空中でガードを押していても HIT、
HOST が正面ガード × GUEST のぽよん・電撃・泡（遅延補償あり）、すれ違い（後ろへ回られた）→ 背面 HIT、ガード解除直後の攻撃、ガード直後の攻撃、連続攻撃のガード。

| 条件 | 実測 ping | 結果 | 押す→GUEST の画面でガード | 押す→HOST で反映（推定） | 押す→HOST の状態が戻る（往復） | 予測と HOST の不一致 | GUARD 重複 / HIT+GUARD 二重 | 被弾補正の snap |
|---|---|---|---|---|---|---|---|---|
| A：約 30ms | 40ms | **23/23** | 平均 7〜13ms（最大 18ms） | 42〜45ms | 69〜138ms | 2（※） | 0 / 0 | 0 |
| B：約 100ms | 109〜115ms | **23/23** | 平均 8〜9ms（最大 18ms） | 81〜87ms | 148〜217ms | 2（※） | 0 / 0 | 0 |
| C：揺らぎあり | 86ms | **23/23** | 平均 11ms | 71ms | 118ms | 2（※） | 0 / 0 | 0 |

※ 不一致 2 回は、背面攻撃とすれ違いの試験で「予測ではガード姿勢・HOST は HIT」を意図的に起こしたもの。どちらも被弾状態へ揺れずに補正（左右の往復 0、snap 0）。
- 全項目でダメージは両画面一致（GUARD は 0）。GUARD の音・演出は GUARD 1 回につき 1 回、命中音なし。ガードの押し戻しの後も位置は一致。
- ガードしていても「ボタンを押してから HOST に届くまで」（上の表の 42〜87ms）より前に来た攻撃は HIT になる（ガード用の遅延補償なし。予定どおり）。

## 3. 通信量（代表テストの実測）
GUEST → HOST 約 5.1 KB/s、HOST → GUEST 約 6.6〜6.7 KB/s（Phase 7：約 4.7 / 6.3）。入力に `"g":0` が増えた分（約 0.4 KB/s）と状態の 4 つの値。極端な増加なし。

## 4. スマホ
GUEST パッドに「防御」ボタン（LEFT / RIGHT の上）。6 つのボタンが重ならず画面内。押す→すぐガード（HOST でも有効）、離す→解除、RIGHT で移動中に防御→止まってガード、
空中で押したまま→空中ではガードせず着地後にガード（v1.0 のまま）、離した後に残らない。HOST のスマホは既存の「防御」ボタンでコタロがガード。

## 7. 既知事項
- Phase 6（クラゲ電撃）・Phase 7（バブルショット）・Phase 8（ガード）は遠隔実機テスト未実施（テスト相手がいないため）。
- Phase 5 の回帰テスト「逃げる相手に補償だけで当たる」はタイミングに左右される項目（Phase 7 では 3 回中 1 回合格、今回は合格）。ネットコードの変更はしていない。
- Phase 7：自分の予測泡は「今」、コタロは 70ms 前の時刻で表示するため、泡が重なって見えてから少し遅れて命中が出る（意図的に残している）。
- ガード用の遅延補償なし：GUEST がガードを押してから HOST に届くまで（片道＋入力の待ち）の間に来た攻撃は HIT。
- ルミポの復帰性能（対人では不利）は把握済み・変更なし。ルミポがガードを使えるのは同期の確認のためで、正式な技構成ではない。

## 8. 遠隔実機で後から確認すること
1. I / 防御ボタンを押した瞬間にガード姿勢が出るか。離すとすぐ戻るか。
2. 「押したのにガードが間に合わない」と感じる頻度（特に相手のぽよんに対して）。
3. 正面は防げて、背面・空中は防げないか。すれ違い直後の向きが自然か。
4. ガード成功時の音・演出が 1 回だけか、命中の音が混ざらないか。両画面のダメージが同じか。
5. 予測ではガードだったのに被弾した時の切り替わりが自然か（揺れないか）。
6. HOST（コタロ）が GUEST の電撃・泡をガードした時に違和感がないか（遅延補償との組み合わせ）。
7. 診断「ガード」の行（入力・HOST の状態・GUARD / HIT・背面 / 空中 / 出始め・不一致・重複・時間）。
8. Phase 6 クラゲ電撃・Phase 7 バブルショットの未実施分。
