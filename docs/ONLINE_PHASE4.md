# コタロの大格闘 Online — Online Phase 4 完成報告

「通常攻撃 1 種類（ぽよんアタック）のオンライン同期実験」。Phase 3 の移動予測はそのまま。
必殺技・泡・ガード・KO・ストック・勝敗・lag compensation・rollback は実装していません。

## 1. 攻撃入力の送り方
- 入力パケット `mi` に `ap`（攻撃ボタンを**押した回数の累計**）を追加。ジャンプの `jp` と同じ考え方で、押しっぱなしでは増えない。
  `{"t":"mi","s":入力番号,"l":0/1,"r":0/1,"j":0/1,"jp":ジャンプ回数,"ap":攻撃回数,"ts":時刻}`
- HOST は `ap` が増えた入力だけを「攻撃を押した瞬間（pressed.attack）」として、その 1 ステップに渡す。押下は 1 ステップに最大 1 回。
- GUEST の操作：PC は J（既存の攻撃キー）、スマホはパッドの「攻撃」ボタン。HOST は J とスマホの既存「攻撃」ボタン。必殺（K）・泡（L）・ガード（I）は引き続き無効。

## 2. 両者がぽよんアタックを使う方法
- 操作実験の間だけ、両者の `selectMove`（技を選ぶ関数）をこのインスタンスだけ「通常攻撃 = ぽよんアタック、それ以外の技は無し」に差し替え。終了時に削除して元に戻す。
- 技データ（`KG.MOVES.poyonAttack`：18F、判定 4〜7F、ダメージ 10%、ノックバック 720/-700、ヒットストップ 5F、前進など）は一切変更していない。
- ルミポもコタロと同じぽよんアタック（同じフレーム・判定・ダメージ）。見た目はルミポの既存の描画にぽよんアタックの拡縮（squash/stretch）がかかる。

## 3. GUEST 側の攻撃予測
- 押した瞬間に、予測用ルミポ（Phase 3 の計算用 Fighter）へ同じ入力を適用 → 既存の Fighter の規則で攻撃が始まれば、その場で画面のルミポにぽよんアタックの見た目を出す（次のフレーム）。
- 予測側では当たり判定（Combat）を**一切行わない**。ダメージ・吹っ飛び・ヒットストップは HOST から届いたものだけを使う。
- 硬直中・被弾中など、既存の規則で出せない時は予測でも出ない（同じ Fighter の処理を使うため）。

## 4. HOST での攻撃開始・命中の確定
- HOST は届いた入力を Phase 3 と同じく 1 ステップ 1 件ずつ既存の `Fighter.update()` に渡す。攻撃が始まるかは既存の規則（技中は出ない・先行入力 0.1 秒・ジャンプキャンセルなど）。
- 命中判定は既存の `Combat.resolve()`（Hitbox × Hurtbox、ダメージ加算、`Knockback.compute`、`receiveHit`、ヒットストップ）がそのまま行う。GUEST の申告は使わない。
- 相打ち：既存の `Combat.resolve()` は全員の当たりを集めてから適用するので、同じステップに当たれば両方に当たる（Version 1.0 と同じ）。HOST の結果をそのまま送る。
- 連打：既存の規則でしか出ないため、J を 30ms 間隔で 20 回押しても攻撃は 3 回、残りは「出せなかった」。異常に速い押下を 120 件送っても 2 回しか出なかった。

## 5. 攻撃 ID の管理
- **攻撃 ID = その攻撃のもとになった「攻撃を押した入力の番号」**。先行入力で後から始まった場合も、最後に押した入力の番号。
- HOST（RemoteInputController）と GUEST の予測（applyCmd）は同じ規則で ID を付けるので、同じ攻撃は同じ ID になる（テストで一致を確認）。
- HOST は状態 `p[17]` に今の攻撃 ID、`p[18]` に最後の押下番号を載せる。GUEST はそれで「HOST がこの攻撃を受理した」ことを確認する。
- 同じ ID の攻撃は 1 回だけ受理として数え、HIT は攻撃ごとに既存の `hitVictims` で 1 回だけ（既存の仕組み）。

## 6. HIT イベント
- HOST で命中したら（既存の `receiveHit` の後に）`mh` を送る：`{id: 命中番号, a: 攻撃した側(0=コタロ / 1=ルミポ), k: 攻撃 ID, d: 当たった側のダメージ（反映後）, x, y: 当たった位置, w: HOST の時刻}`
- GUEST は `id` が前回より大きいものだけ処理（二重表示なし・古いものは無視）。ヒットエフェクト・ヒット音・白く光る演出を出し、HUD のダメージを HOST の値にする。
- MISS は特別なイベントを送らない。ただし診断のため、GUEST の攻撃が終わった時に HOST での結果 `ma`（HIT / MISS と、判定が出た瞬間の両者の位置）を送る。ゲーム結果には使わない。

## 7. ダメージ・吹っ飛びの同期
- ダメージ：HOST の `status.damage` を状態 `f[i][7]` と HIT イベントで送り、GUEST の HUD はその値を表示。全条件で終了時のダメージが両画面で一致。
- 吹っ飛び：HOST の既存処理で決まった位置・速度・被弾硬直・ヒットストップ・傾きを状態で送る。コタロ（GUEST から見て遠隔）は Phase 2 と同じ補間表示、ルミポは下の方法。終了時の位置の差は 0.03 以下。

## 8. GUEST が被弾した時の予測
- HOST の状態で GUEST のルミポがヒットストップ中・被弾硬直中、または命中イベントで被弾が分かった時は「被弾による作り直し」として扱う：
  1. 予測用ルミポを HOST の被弾状態（位置・速度・被弾硬直・ヒットストップ）に置き換え
  2. 未確認入力を重ねる（既存の Fighter は被弾硬直中に入力を受け付けないので、歩き続けない）
  3. 差は速め（時定数 30ms）に表示から消す。300 以上なら即座に HOST の位置へ
- 予測誤差とは別に「被弾/命中の補正」として数える。被弾中は予測と HOST が同じ物理で動くので、HOST ↔ 予測の往復は起きない（テストで方向の反転 1 回以下）。

## 9. ヒットストップ
- HOST：既存どおり（攻撃側・受け側とも 5F 停止）。
- GUEST：HOST の状態のヒットストップ・被弾硬直・傾きを表示用 Fighter に設定し、既存の描画（震え・回転）で表示。命中イベントで白く光らせ、エフェクトと音を出す。完全なフレーム同期はしていない。

## 10. 攻撃が拒否された時
- HOST で攻撃が始まらなかった（出せない状態だった）場合、次の作り直しで予測の攻撃は消える。その時、見た目のぽよんアタックは最後のフレームまで再生して自然に終える（巻き戻さない）。被弾した時は即座にやめる。
- GUEST の診断に「HOST で出なかった」回数を表示（1.5 秒以内に HOST の受理が確認できなかった予測攻撃）。

## 11. 見た目の当たりと HOST 判定の比較（診断だけ）
- GUEST の画面で、予測した攻撃の判定フレームに、自分のルミポの攻撃判定が**画面上のコタロ（補間表示）**の Hurtbox と重なったかを記録。ゲーム結果には使わない。
- HOST から届く結果（`ma`）と照合して 4 分類を数える。判定が出た瞬間の「自分の画面のコタロの位置」と「HOST のコタロの位置」の差も記録。

### 読み取れること（Phase 5 の判断材料）
- **自分の攻撃が出るまで**はどの Ping でも 1 フレーム前後（予測が効いている）。
- **見た目と HOST 判定のズレ**：判定の瞬間、自分の画面のコタロは HOST の実際の位置から平均 46（Ping 30ms）〜112（Ping 200ms）ずれていた（コタロの体の幅は 76、ぽよんアタックの判定の幅は 84）。
  - ズレの中身 ＝ コタロの表示の遅れ（片道 + 補間 70ms + 状態の間隔）＋ 自分の攻撃が HOST に届くまでの時間。動いている相手ほど大きい。
  - 結果として、このテスト（コタロが常に左右に動く最も厳しい条件）では「見た目は当たったのに HOST では外れ」が見た目 HIT の約半分〜6 割。「見た目は外れたのに HOST では当たり」は少ない（0〜2 回）。
  - 相手が止まっている・ゆっくり動いている時はズレは小さい（テスト 2：静止したコタロへの攻撃は見た目 HIT / HOST HIT）。
- 予測誤差（被弾以外）は Phase 3 と同程度（入力が HOST に間に合わなかった時の 1 ステップ分）。snap は 0。
- 被弾時の補正は 30〜120 程度が多く、速めに吸収。Ping 200ms で 1 回だけ 351 の被弾補正が snap になった。

- 状態 1 件は最大 約 500 文字（上限 1024）。予測の作り直しのためルミポの値は丸めずに送っている。

## 14. スマホ
- GUEST のパッドに「攻撃」ボタン（JUMP の左）を追加。LEFT / RIGHT を押しながら攻撃、JUMP しながら空中攻撃（3 本指）ができる。タッチした次のフレーム（2〜4ms 後）に予測攻撃が表示された。
- HOST のスマホは既存のスティック・ジャンプ・攻撃ボタン（必殺・泡・防御は隠す）。

## 15. セキュリティ
- `ap` は 0 以上の整数で、減らない（減ったら破棄）。小数・負の値は破棄。キーの数・サイズも検証。
- GUEST から送られた `mh`（命中）・`ma`（結果）・`st`（状態）は HOST では受け付けない。ダメージ・吹っ飛び・位置などを GUEST が送っても使われない（テストで確認）。
- 入力の頻度上限（150 件/秒）と既存の攻撃の硬直により、高速な押下でも攻撃は既存のフレームより速く出ない。

- 通信バージョン 4（新旧のページが混ざると接続を断る → 両方再読み込み）

- `st`：`f`（各キャラ）に ダメージ・技のフレーム・傾き を追加、ヒットストップ中・被弾硬直中のフラグ。`p`（ルミポ）に 技のフレーム・攻撃の先行入力・ヒットストップ・被弾硬直・傾き・攻撃 ID・最後の押下番号 を追加（19 個）

## 19. 遠隔実機で確認してほしいこと（主に予測 ON）

3. 近距離で普通に殴り合えるか（HOST のコタロも攻撃）
