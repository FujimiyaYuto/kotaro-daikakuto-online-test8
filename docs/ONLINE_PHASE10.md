# コタロの大格闘 Online — Online Phase 10 完成報告

「試合の流れ（Match Lifecycle）と再戦」。Phase 9 までの対戦（HOST authoritative・予測と補正・補間 70ms・遅延補償 200ms・泡・ガード・KO / 3 ストック / 勝敗 / DRAW）は
そのまま使い、**接続 → READY → 3 / 2 / 1 / START! → 対戦 → 決着 → 勝敗表示 → 再戦 → 次の試合** を、同じ P2P 接続のまま何試合でも続けられるようにしました。
技・移動・吹っ飛び・ルール（3 ストック・リスポーン 1 秒・無敵 2 秒）・カウントダウンと勝敗表示の時間（Version 1.0 の `KG.CONFIG.match`）は変更していません。

## 1. 試合の流れ
| 段階 | 画面 | 決める側 | 内容 |
|---|---|---|---|
| ロビー（CONNECTED / READY） | 接続画面 | HOST | 両方の READY / NOT READY を表示。両方が READY → HOST が既存の開始手順（`ms` / `mr`）でゲーム画面へ |
| COUNTDOWN | ゲーム画面 | HOST | 既存の `Game.phase = 'countdown'`（3 → 2 → 1、各 0.7 秒）。両者とも操作できない |
| FIGHT | ゲーム画面 | HOST | HOST の GO（既存の `updatePhase`）を GUEST が受け取ってから操作開始。START! 表示 |
| ENDING | ゲーム画面 | HOST | Phase 9 の決着（`result` / `winner`）。1.3 秒 |
| RESULT | 勝敗表示 | HOST | 「コタロ WIN」「ルミポ WIN」「DRAW」（既存の表示）＋「もう一度」「終了する」 |

- 試合ごとに HOST が **match gen**（試合の番号。再戦ごとに +1）を決める。HOST は段階が変わった時と 0.5 秒ごとに **`ml`**（試合の番号・段階・GO までの残り・結果・再戦希望）を送る。
  GUEST は自分では段階を進めない（カウントダウンの開始・GO・勝敗表示は `ml` か状態 `st` の段階 `l` で）。
- 「終了する」（または「実験を終了」）は既存の終了（`me`）。どちらが押しても両方とも接続画面（両方 NOT READY）へ戻る。切断時の処理は変更なし。

## 2. READY
- 接続画面の既存ボタン（以前の「操作実験を開始」）を READY / 「READY を取り消す」に。HOST・GUEST どちらにも表示し、`HOST：READY　GUEST：NOT READY` のように両方の状態を出す。
- GUEST → HOST は `rd`（`m=0` ＝ ロビー、`r=1/0`）。状態なので重複・再送しても同じ結果。HOST は自分が確認した両方の値を `ml`（`s=0`）で返し、GUEST はそれを表示
  （自分の値が HOST に届くまでは「（確認中）」）。
- 試合が始まった時・接続画面に戻った時・切断時は両方 NOT READY に戻す。終わった試合の再戦希望（`m≠0`）が遅れて届いてもロビーの READY にはしない。

## 3. カウントダウンの同期
- HOST は `ml` に `w`（HOST の `performance.now()`）と `cd`（GO までの残り ms）を載せる。GUEST は既存の Ping が推定した時計のずれ（`session.clockOffset`。往復時間が最短の時の値）で
  `GO の自分の時刻 = w − clockOffset + cd` に直し、3 / 2 / 1 をその時刻から逆算して表示する（ずれの推定が無い間は「受信時刻 − RTT/2」）。0.5 秒ごとの再送で更新。
- START!（操作の開始）は HOST が GO を確定した合図を受けてから（GUEST が自分の時計だけで対戦を始めることはない）。表示の START! は GO の時刻から数える。
- 新しい時計同期の仕組みは作っていない（Phase 2 からの Ping の値をそのまま使う）。

## 4. カウントダウン中・勝敗表示中の入力
- HOST：既存の `Game.step` が対戦中以外の入力を捨てる（コタロもルミポも）。GO の瞬間の `input.poll()`（押した瞬間を捨てる）も既存のまま。
  さらに GUEST の入力は「今の試合の番号で、今が対戦中」でなければ何も押していない入力として並べる（入力番号・押した回数の記録だけ進める）。Phase 3 の追いつきも対戦中だけ（Phase 9）。
- GUEST：対戦中以外は何も押していない入力だけを送り、予測しない（未確認入力にも積まない）。ジャンプ・攻撃・必殺・泡の押した回数も増やさないので、
  カウントダウン中・勝敗表示中に押したものが GO の後に出ることはない。
- 押しっぱなし（移動・ガード）は Version 1.0 と同じく「GO の瞬間に押している状態」がそのまま有効（押しっぱなしのまま GO を迎えれば GO から動く。離していれば動かない）。

## 5. 新しい試合の初期化
- ゲームの状態：既存の `startMatch`（`resetTest`）＝ 出現位置・速度・ダメージ 0・ストック 3・復帰待ち・無敵・技と技のフレーム・被弾硬直・ヒットストップ・ガード・
  再使用待ち・先行入力・場の泡・演出・勝敗（`result` / `winner`）。HOST・GUEST の両方で行う。
- HOST のネットワーク側：GUEST の未適用の入力・押しっぱなしの状態・押下の記録（`RemoteInputController.resetMatch`）、技の追跡、遅延補償の履歴、KO の記録（Phase 9 の `newKO`）。
- GUEST のネットワーク側：予測用ルミポ（作り直し）・未確認入力・表示のずれ・被弾補正・見た目だけの技・補間の履歴（`snaps` など）・予測泡と消えた泡の記録・命中と KO の記録・技の表示・勝敗。
- 接続中ずっと増え続ける値（試合ごとに戻さない）：入力番号・押した回数の累計・状態番号・命中番号・泡の ID・KO 番号・攻撃 ID。試合をまたいでも番号が重ならない。

## 6. match gen
- `st` / `mh` / `mk` / `pe` / `ma`（HOST → GUEST）と `mi`（GUEST → HOST）に `m` = 試合の番号を付ける（`PROTO_VERSION` 10）。
- GUEST は今の試合の番号でないものを捨てる（診断「古い試合の受信」）。新しい番号の `ml` が来たら前の試合の状態をすべて捨てて初期化。
- HOST は今の試合の番号でない入力を「何も押していない」として扱う。再戦希望 `rd` は終わった試合の番号が今の試合と同じ時だけ数える。
- 既存の seq / ack / 攻撃 ID / Projectile ID / 命中番号 / KO 番号は今までどおり（試合の番号は「どの試合のものか」だけを表す）。

## 7. 勝敗表示と再戦
- 勝敗は Phase 9 のまま（HOST が決め、`mk` の `r` と `st` の `r` で同期）。勝敗表示への切り替えは HOST の `ml`（`s=4`）。表示は既存の `#ko-overlay`。
- オンラインの時だけ既存の「もう一度」「タイトルへ戻る」の代わりに「もう一度」「終了する」と状態の文（「相手を待っています…」「相手が再戦を希望しています」）を出す。Enter でも「もう一度」。
- 両方の「もう一度」を HOST が確認したら、新しい match gen → 初期化 → カウントダウン。
- 勝ち負けの決め方は `resultFor()` の 1 か所（今は「同じステップで 2 人とも最後のストック → DRAW」。サドンデスなどに変える時はここ）。
- カウントダウンの数字と勝敗表示は、診断パネルより手前に表示する。

## 7.1 変更後の Phase 9 との違い
- GUEST の勝敗表示への切り替えは Phase 9 では自分の 1.3 秒のタイマー、Phase 10 では HOST の合図（同じ 1.3 秒・片道の遅れ分だけ後）。
- Phase 9 の「終了後は『実験を終了』で接続画面へ」は「もう一度」「終了する」に変更。

Phase 10 テストの内容（1 回の実行で試合 #1〜#4 を同じ接続で続ける）：
- HOST だけ READY → 始まらない / GUEST だけ READY（2 回送信）→ 始まらない / 両方 READY → 両画面で試合 #1 のカウントダウン
- カウントダウン中に両者が移動・ジャンプ・攻撃・必殺・泡・ガード → 動かない・技なし・GUEST は予測なし・押した回数が増えない → GO 後も暴発しない
- GO 後は両者とも操作できる（GUEST の右移動が HOST に反映・HOST の攻撃が出る）
- 試合 #1：HOST WIN（最後の KO の直前に両者が泡）→ 両画面で同じ勝敗表示
- GUEST だけ「もう一度」→ 始まらない（GUEST「相手を待っています…」/ HOST「相手が再戦を希望しています」）→ HOST も → 試合 #2
- 試合 #2 の初期化：stock 3/3・damage 0・出現位置・泡 0（両画面）・KO 0・勝者なし・GUEST の未確認入力 0・予測位置 = 出現位置・入力番号は続き（古い / 不正な入力 0）
- 試合 #1 の命中・KO・泡・試合状態（GUEST へ）と入力（HOST へ。攻撃を押したもの）を試合 #2 へ届ける → すべて捨てられ、影響なし
- 勝敗表示中に GUEST が攻撃・ジャンプ・右押しっぱなし → 試合 #2 の GO 後に出ない
- 試合 #2：GUEST WIN（両画面一致）→ HOST が先に「もう一度」→ GUEST → 試合 #3
- 試合 #3：予測 = HOST（静止後の位置が一致・snap 0・予測誤差 最大 15 / 3）、KO → stock 2 → リスポーン（damage 0）、同じステップの最後の KO → DRAW（両画面一致）
- 勝敗表示で GUEST が再戦希望中に HOST が「終了する」→ 両方とも接続画面（NOT READY）。遅れて届いた試合 #3 の再戦希望はロビーの READY にならない
- 同じ接続で再び READY → 試合 #4（stock 3/3）・操作と予測が正常 → GUEST が終了 → HOST も接続画面へ

カウントダウンの表示の差（GUEST − HOST。同じマシンの実時刻で比較・描画 1 フレーム ≈ 16ms の誤差を含む）：
| 条件 | 「3」が出る | 「2」 | 「1」 | START! |
|---|---|---|---|---|
| 片道 15ms（試合 #1 / #2 / #3） | 79〜104 / 37 / 25ms | 27 / 4 / 15ms | 10 / 27 / 12ms | 47 / 64 / 38ms |

描画の遅れも入る）。START! は HOST の GO の確定を待つので片道＋描画分だけ遅れる（予定どおり）。

## 10. 既知事項
- 遠隔実機テストは未実施（Phase 6〜9 と同じ）。
- 「3」の表示は GUEST で片道ぶん短い（開始の合図を受け取ってから表示するため）。「2」「1」はそろう。START! は片道ぶん遅れる（GO の確定を待つため）。
- 押しっぱなしの移動・ガードは GO の瞬間から有効（Version 1.0 と同じ）。押した瞬間（ジャンプ・攻撃・必殺・泡）は GO 前のものは出ない。
- 診断「古い試合の受信」には、GUEST が最初の合図を受け取る前（番号 0）に送った何も押していない入力も数えられる。
- Phase 9 までの既知事項（ガード用の遅延補償なし・泡の表示差・ルミポの復帰性能・高遅延時の予測必殺の一瞬の VFX・終了後の場外は表示から外すだけ）は変更していない。

## 11. 遠隔実機で後から確認すること
1. READY の表示（自分・相手）がすぐ変わるか。片方だけでは始まらないか。
2. 3 / 2 / 1 / START! が両方の画面でほぼ同時に見えるか（特に「2」「1」）。カウントダウン中にキーを押しても何も起きないか。
3. 勝敗表示が両方で同じか。「もう一度」で「相手を待っています…」→ 両方押して次の試合が 3/3・0% から始まるか。
4. 3 試合以上続けても、前の試合の泡・ダメージ・ストック・勝敗が残らないか。
5. 勝敗表示で片方が「終了する」を押した時、もう片方が接続画面へ戻るか。
